# Core Hook API Reference

This page lists the core library hooks a plugin calls across FFI. Hooks split into **registration primitives** (called once during `on_init_plugin`) and **query/state functions** (called while handling a command or drawing a frame).

> Signatures below are expressed in Rust. The exact `extern "C"` function-pointer types are generated by `cli-core-types/build.rs` from every `#[register_hook]` function in `cli-core`, and re-exported from `cli_core_types`. The build script maps a snake_case hook name to a `PascalCaseFn` type: `register_option` → `RegisterOptionFn`.

## Resolving core symbols

In `on_init_plugin`, open the core library from `HostMetadata.cli_core_path`, then use the `cli-core-macros` procedural macro to resolve symbols:

```rust
use cli_core_macros::load_core_symbols;

let lib = init_library(&h_meta.cli_core_path);
load_core_symbols!(lib, register_option, register_menu_item);
// After the macro, `register_option` / `register_menu_item` are local bound symbols.
```

The macro expands to a `libloading::Symbol<cli_core_types::RegisterOptionFn>` lookup for each listed name. Symbols are looked up by the raw symbol string (`"register_option\0"`).

Conventions used by every hook:

- Input strings are `&safer_ffi::String`; numbers are `&i32`/`&u64`.
- Output buffers are `Out<'_, T>`; the host owns the buffer and the plugin writes into it.
- Return value: `cli_core_types::Result` (`code == 0` success).
- Plugin state that must outlive a single call is held in the plugin's own `LazyLock`/`OnceLock`/`Mutex`; core-owned state lives in the core library.

## Options

| Hook | Signature | Purpose |
| --- | --- | --- |
| `register_option` | `fn(&String) -> Result` | Register an accepted option key. Keys are stored case-insensitively, normalized to uppercase. Idempotent |
| `option_is_registered` | `fn(&String) -> Result` | Check whether an option key is registered; success = registered, error = not found |
| `get_registered_options` | `fn(Out<Vec<String>>) -> Result` | List all registered option keys (for completion) |

Unguarded keys are rejected by `set`/`setg`, so a plugin that introduces its own settings must register them here.

## Menu items

`register_menu_item` — register one menu entry:

```
fn(
    label: &String,        // visible menu label
    group: &String,        // menu group (top-level menu name)
    accel: &String,        // group mnemonic letter (underlined Alt+key)
    action_kind: &i32,     // ui_action_kind::RUN or FORM
    argv: &String,         // whitespace-separated command line (RUN action)
    form_cmd: &String,     // form spec command name (FORM action; empty for RUN)
) -> Result
```

`get_menu_items(out)` returns every registered item as flat rows: `label|group|accel|kind|argv|form_cmd`.

Action kinds (`cli_core_types::ui::ui_action_kind`):

| Constant | Value | Meaning |
| --- | --- | --- |
| `RUN` | 0 | Run the command line in `argv` directly |
| `FORM` | 1 | Open the parameter form registered under `form_cmd` |

## Forms

| Hook | Signature | Purpose |
| --- | --- | --- |
| `register_form_spec` | `fn(title: &String, cmd: &String, prefill: &String) -> Result` | Register a form skeleton: title, the submit command, and the input-box prefix |
| `register_form_field` | `fn(form_cmd: &String, label: &String, required: &i32, secret: &i32, kind: &i32) -> Result` | Append a field to the form identified by `form_cmd` |
| `get_form_spec` | `fn(form_cmd: &String, Out<Vec<String>>) -> Result` | Fetch a form spec: first row `SPEC|title|cmd|prefill`, then `FIELD|label|required|secret|kind` rows |

Field completion kinds (`cli_core_types::ui::ui_field_kind`):

| Constant | Value | Completion source |
| --- | --- | --- |
| `PLAIN` | 0 | Free text |
| `MEMBER` | 1 | Sidebar member snapshot |
| `REMOTE_PATH` | 2 | Remote directory listing |
| `LOCAL_PATH` | 3 | Local filesystem path |
| `OPTION_KEY` | 4 | Registered option keys |
| `SUBCOMMAND` | 5 | Command subcommands |
| `PLUGIN` | 6 | Loaded plugin names |
| `NAMESPACE` | 7 | Loaded namespaces |
| `NO_COMPLETION` | 8 | No completion |

`secret != 0` masks input (password field); `required != 0` marks a mandatory field.

## Sidebar sections & entries

| Hook | Signature | Purpose |
| --- | --- | --- |
| `register_side_section` | `fn(id: &String, title: &String, default_open: &i32, source: &String) -> Result` | Register a collapsible section shell. `source` names the snapshot it backfills (`sessions`/`members`/`plugins`) |
| `register_side_item` | `fn(section: &String, prefix: &String, label: &String, highlight: &i32, line: &i32) -> Result` | Register an entry template under a section. `label` uses `{name}`/`{namespace}` placeholders; `highlight` marks the current/highlighted entry; `line` 0 = primary row, 1 = secondary row |
| `get_side_sections` | `fn(Out<Vec<String>>) -> Result` | Rows: `id|title|default_open|source` |
| `get_side_items` | `fn(Out<Vec<String>>) -> Result` | Rows: `section|prefix|label|highlight|line` |

The host fills actual entry names from its sidebar snapshots; the plugin supplies only the template and prefixes.

## Status bar

| Hook | Signature | Purpose |
| --- | --- | --- |
| `register_bottom` | `fn(label: &String) -> Result` | Register a static status-bar fragment |
| `register_bottom_callback` | `fn(&BottomFragmentFn) -> Result` | Register a per-frame callback returning the current fragment text; empty string means no fragment this frame |
| `get_bottom_fragments` | `fn(Out<Vec<String>>) -> Result` | Static fragments plus non-empty callback results |

`BottomFragmentFn` is `unsafe extern "C" fn() -> safer_ffi::String`. Function-pointer deduplication uses `std::ptr::fn_addr_eq`.

## State & query

| Hook | Signature | Purpose |
| --- | --- | --- |
| `get_global_option` | `fn(key: &String, Out<TaggedOption<String>>) -> Result` | Read a global option; `None` if unset |
| `get_session_option` | `fn(key: &String, Out<TaggedOption<String>>) -> Result` | Read a session option; falls back to global semantics handled by the caller |
| `set_current_freq` | `fn(&String) -> Result` | Set the active frequency |
| `get_current_freq` | `fn(Out<TaggedOption<String>>) -> Result` | Read the active frequency |
| `add_progress` / `set_progress` / `get_progress` | see `cli-core/src/init.rs` | Startup progress counter |

Additional grouped hooks exist for global/session settings, aliases, and macros; their generated types follow the same naming scheme in `cli_core_types` (e.g. `SetAliasFn`, `GetAllAliasesFn`, `SetGlobalOptionFn`).

## Plugin registry

| Hook | Signature | Purpose |
| --- | --- | --- |
| `register_plugin` | `fn(&PluginMetadata) -> Result` | Register plugin metadata (core-internal; standard plugins register through the load flow) |
| `unregister_plugin` | `fn(&String) -> Result` | Call the plugin's `on_shutdown_plugin`, then remove its metadata/namespace/global-command entries and unregister every option/UI entry owned by it |
| `get_plugin` | by name / command name | Look up a registered plugin metadata clone |
| `get_all_plugins` | `fn(Out<Vec<PluginMetadata>>) -> Result` | List all registered plugins |
| `load_plugin` | `fn(&String) -> PluginResult` | Locate and load a plugin by name |
| `is_plugin_name_registered` / `is_plugin_command_name_registered` | `fn(&String) -> Result` | Existence checks for completion |

Registered entries (option keys, menu items, form specs/fields, sidebar sections/items, bottom fragments and per-frame callbacks) record the owning plugin through an internal core owner context set during `on_init_plugin`; the FFI registration primitives take no owner parameter. On unload, entries matching that owner are dropped; persisted aliases are user configuration and are not removed.

## Server hooks

Server plugins resolve these symbols from `srv-core` (see `crates/srv-standard/src/lib.rs`):

| Hook | Signature | Purpose |
| --- | --- | --- |
| `register_channel` | `fn(&ChannelMetadata) -> Result` | Register a channel (name, type, description, version, author, capacity) |
| `set_channel_handler` | `fn(&String, ChannelHandlerFn) -> Result` | Bind a handler to a registered channel name |

`ChannelHandlerFn` is `extern "C" fn(*const Packet) -> PacketResult`. The host core calls it with a borrowed `Packet`; the handler decodes the base64/prost request, produces a response, and returns a `PacketResult` with the base64-encoded response payload.

Server push (not a registered channel handler): the plugin resolves `tc_srv_pusher_push` (`extern "C" fn(*const c_char, *const u8, u32) -> i32`) to push an encoded `Packet` frame to an online user outside the request/response cycle.

## Available channel types

`cli_core`-side server channel metadata uses `srv_core_types::channels::channel_type`: `CHAT = 0`, `CALL = 1`, `FILE = 2`, `BROADCAST = 3`, `CUSTOM = 4`.
