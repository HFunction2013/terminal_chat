# Contributor Guide

This directory is for contributors who work on the framework itself: the host binaries, the core libraries, the FFI boundary, and the shared TUI framework. To write or extend a plugin instead, start from the [developer documentation](../developer/README.md).

## Architecture at a glance

Terminal Chat is a **host + core library + plugin** system, duplicated on two sides:

- **Client side**: `cli` host → `cli-core` core library → client plugins (e.g. `cli-standard`).
- **Server side**: `srv` host → `srv-core` core library → server plugins (e.g. `srv-standard`).

Hosts parse input and own the terminal/socket lifecycle; core libraries own registries, state, and hook dispatch; plugins contribute commands, UI, and business rules across a C ABI. The host embeds no plugin-specific menu, sidebar, or status-bar knowledge — all of it is registered through core hooks and rendered from registries.

## Crate map

| Crate | Role |
| --- | --- |
| `crates/cli` | Client host binary. REPL (`rustyline`) and full-screen TUI (`edit-tui`); loads `cli-core` and client plugins; owns the input event loop and command dispatch |
| `crates/srv` | Server host binary. TCP listener (dual-stack IPv6/IPv4), per-connection sessions, handshake, packet dispatch, disconnect cleanup |
| `crates/cli-core` | Client core cdylib. Plugin/option/command-table/state/UI registries, command runner, push queue, terminal hooks, progress counter |
| `crates/srv-core` | Server core cdylib. Channel registry, session table, packet router, plugin loading, push pusher |
| `crates/cli-core-types` | ReprC types and function-pointer types crossing the client FFI boundary; hook types are generated by `build.rs` into `fn_type.rs` |
| `crates/srv-core-types` | Server-side ReprC types and channel/packet/session/plugin contracts |
| `crates/cli-core-macros` | Procedural macro `load_core_symbols!` that resolves core symbols into bound function pointers in a plugin |
| `crates/plugins/cli-standard` | Reference client plugin: standard commands, forms, menus, sidebar sections/items, status bar, completion sources |
| `crates/plugins/example` | Minimal compilable client plugin: single `example hello [who]` command and one registered option, used as a developer scaffold reference |
| `crates/plugins/srv-standard` | Reference server plugin: frequencies, users, messaging, calls, moderation, remote virtual filesystem, notifications |
| `crates/plugins/ai-glm`, `translations`, `werewolf` | Optional / example plugins |
| `crates/edit-tui` | Retained-mode TUI framework: component tree, framebuffer diff, layout, input, clipboard, unicode/ICU, color math, suspend/resume terminal state |
| `crates/protos` | prost-generated message types from `proto/**/*.proto`; vendored protoc so CI needs no system install |
| `crates/helper/cmd-gen` | CLI helper that generates per-command Rust skeletons and `mod.rs` from `commands.yaml` |
| `crates/lsh` | Syntax-highlighting definition language: compiler to bytecode and line-oriented runtime |
| `crates/neo-lolcat`, `crates/sl-rs`, `crates/rs-fortune` | Decorative/auxiliary helpers: lolcat coloring, SL locomotive animation, fortune quotes |

## Reading path

1. [architecture.md](architecture.md) — Layering, the FFI boundary, dynamic loading, wire protocol, the client event loop and state snapshots, and the hook-chain generation mechanism.
2. [workflow.md](workflow.md) — Build/test/CI commands, code style, the `cmd-gen` skeleton rules, branch and issue workflow.

## Where to look first

- Host dispatch and event loop: `crates/cli/src/main.rs`, `crates/cli/src/tui.rs`, `crates/cli/src/ui_registry.rs`
- Core registries: `crates/cli-core/src/registered_ui.rs`, `registered_options.rs`, `registered_commands.rs`, `plugins.rs`
- Server routing: `crates/srv-core/src/channels.rs`, `packets.rs`, `plugins.rs`
- Reference plugin behavior: `crates/plugins/cli-standard/src/`, `crates/plugins/srv-standard/src/`
